The Harness Is Part of the Benchmark

A controlled audit of prompt and extraction sensitivity in the POPE object-hallucination benchmark.

Ridoy Kumar Adhikary Sichuan University Software Engineering
Read the Paper  → View Code on GitHub  ↗
Abstract

Summary of the Paper

POPE is a widely used benchmark for evaluating object hallucination in Vision-Language Models (VLMs), yet its scoring harness relies on a matching-based method that is highly under-specified in the literature. In this audit, we evaluate Qwen2.5-VL-7B on 9,000 POPE questions across 4 prompt templates and 6 answer-extraction rules. We find that the model's reported F1 score swings from 0.000 to 0.868 depending entirely on the evaluation harness. Specifically, strict exact-matching (R1) yields an F1 of 0.000 on standard prompts because the model answers in natural language, while substring-matching (R3) recovers the score to 0.836. Furthermore, forcing a one-word answer (Prompt P6) artificially inflates the score to 0.861. We conclude that benchmark scores are highly sensitive to under-specified scoring rules and propose a minimal reporting checklist to ensure evaluation transparency.

The Problem & Solution

What this project solves, step-by-step

Modern AI evaluations are often treated as absolute truth, but they are actually pipelines of code that can introduce massive bias. Here is how we broke down the problem and designed a controlled solution.

Problem 1: Brittle Parsers

Standard evaluations assume the model will output exactly "Yes" or "No". If the model outputs "Yes, there is a dog," strict parsers crash and mark it as wrong, completely masking the model's true capability.

Solution 1: Extraction Rule Audit

We implemented 6 distinct extraction rules (R1-R6), ranging from strict exact-match to probability-based log-likelihood, to prove how much the parser alone changes the final score.

Problem 2: Prompt Variability

Researchers often rephrase the same question without realizing that slight wording changes can drastically alter how a VLM formats its output.

Solution 2: Prompt Template Isolation

We tested 4 distinct prompt templates (Standard, Wording, Soft Format, Strict Format) across 9,000 questions to measure the exact variance introduced by phrasing alone.

Problem 3: Uncontrolled Environments

If a model generates different answers on different runs (due to stochasticity), you can't isolate the effect of the evaluation code.

Solution 3: Frozen Outputs

We generated 36,000 responses once and froze them in JSONL format. All subsequent scoring was done on this static dataset, guaranteeing absolute reproducibility.

How the audit works

Controlled evaluation architecture

The pipeline is designed to decouple the AI model from the measurement tool. By freezing the outputs at the earliest possible stage, we guarantee that any downstream score differences are caused entirely by the harness.

Scope

Limitations and Future Work

Due to shared-server network restrictions (specifically, firewalls blocking AWS CDN and PyPI), this audit evaluated only one model: Qwen2.5-VL-7B. Models such as LLaVA-1.5 and InternVL2 could not be downloaded.

Despite this single-model constraint, the effect is so extreme (an 86-point swing) that it is highly likely to generalize across other model architectures. Future work will extend this audit to multi-model comparisons and apply the same harness-sensitivity analysis to other multimodal benchmarks such as MMMU and SEED-Bench.
